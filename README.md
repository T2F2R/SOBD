# Нейросетевой анализ требований работодателей и динамики востребованности навыков

Курсовая работа. Цель: извлекать навыки из текстов вакансий нейросетью и анализировать, как меняется их востребованность во времени.

**Статус:** готовы данные, словарный baseline и обученная модель извлечения навыков (BERT). Не сделаны: применение модели ко всем вакансиям, анализ динамики по найденным навыкам, нормализация навыков, ручная проверка качества.

---

## 1. Данные

**Основной датасет:** The vacancies data in artificial intelligence (Mendeley Data, Томский государственный университет), DOI `10.17632/wyjh8c4ywr.1`.

| Параметр | Значение |
|---|---|
| Вакансий | 3 626 (2 673 после фильтра по ролям) |
| Источники | hh.ru (3 616), «Работа России» (9), SuperJob (1) |
| Период | 10.10.2023 – 27.05.2024 (≈ 8 месяцев) |
| Месяцев с ≥ 100 вакансий | 7 из 8 (октябрь 2023: 15 вакансий) |
| Заявленные навыки (`raw_skills`) | есть у 3 147 вакансий, в среднем 4–5 на вакансию |
| Уникальных навыков | 598, из них 200 встречаются один раз |
| Текст | поле `description`, в среднем ≈ 2 100 символов |

**Ограничения данных (учитывать в тексте работы):**
- `last_found_at` — дата, когда парсер последний раз видел вакансию, а не дата публикации.
- Навыки в `raw_skills` — то, что работодатель отметил в форме. Многие навыки названы только в тексте. Часть заявленных навыков абстрактна («аналитическое мышление») и в тексте буквально не встречается.
- Выборка «по ИИ» содержит шум: копирайтеры, операторы ПК и др. Ноутбук по умолчанию оставляет только релевантные роли (список `RELEVANT_ROLES`, его нужно проверить под свои цели).
- Объём небольшой: помесячные доли шумные, делать выводы о трендах без доверительных интервалов нельзя.

**Что не подошло:**
- *API hh.ru*: с апреля 2026 года метод поиска вакансий требует авторизации и фактически доступен только работодателям и рекрутинговым сервисам.
- *LinkedIn Job Postings (Kaggle)*: 98,5% вакансий опубликованы в апреле 2024, динамику построить нельзя; навыки в нём — 35 крупных категорий, а не конкретные навыки.

## 2. Методы

1. **Нормализация навыков.** Словарь синонимов (`ML`, `Машинное обучение` → `machine learning` и т. д.). Сейчас покрывает лишь несколько навыков; планируется заменить эмбеддингами.
2. **Baseline.** Словарь из заявленных навыков (частота ≥ 5) и поиск в тексте: (а) точное совпадение строки, (б) совпадение по леммам (pymorphy3).
3. **Слабая BIO-разметка.** Заявленные навыки ищутся в тексте с лемматизацией и разворачиванием синонимов, найденные спаны получают метки `B-SKILL` / `I-SKILL`, остальное — `O`. Размечено 2 108 вакансий, 17 133 токена в навыках (2,2% токенов). Разбиение по вакансиям: 1 687 / 211 / 210 (train / val / test).
4. **Модель.** Дообучение `DeepPavlov/rubert-base-cased` для token classification. Настройки по умолчанию: 6 эпох, lr 3e-5, batch 16, фрагменты по 100 слов, выбор лучшей эпохи по F1 на валидации.

## 3. Результаты

### Baseline против заявленных навыков (вся выборка с разметкой, 2 185 вакансий)

| Метод | Precision | Recall | F1 |
|---|---|---|---|
| Точное совпадение строки | 0,395 | 0,564 | 0,465 |

Лемматизация и разворачивание синонимов увеличили долю заявленных навыков, найденных в тексте, с 56,4% до 66,6%.

### Тест (210 вакансий, сравнение на уровне вакансии)

| Метод | Precision | Recall | F1 |
|---|---|---|---|
| Baseline (словарь + леммы) | 0,394 | 0,796 | 0,527 |
| BERT | 0,733 | 0,845 | 0,785 |

### Как интерпретировать
- Эталон слабый: «правильными» считаются навыки из формы работодателя, найденные в тексте. Precision занижена для baseline и, вероятно, отчасти отражает то, что модель выучила стиль разметки («какие навыки работодатели обычно отмечают»). Настоящий precision можно получить только ручной проверкой.
- В baseline нет разворачивания синонимов, а в эталоне оно есть, поэтому его recall искусственно ниже. Для честного сравнения нужен baseline с теми же синонимами.
- Один запуск, один seed, 210 тестовых вакансий: доверительных интервалов нет.

### Динамика (заявленные навыки, доля вакансий месяца)
Самые частые навыки: Python (≈ 56–70% по месяцам), machine learning (≈ 41–55%), SQL (≈ 15–30%), PyTorch, NLP, PostgreSQL, Docker, Git. Отдельные скачки (например, Linux в феврале 2024: 17,8% при 5–9% в остальные месяцы) без интервалов и прогноза трендами считать нельзя.

5. Честный baseline с разворачиванием синонимов; повторы обучения с разными seed.
6. Анализ лога обучения (кривые `eval_f1` по эпохам) на предмет переобучения.
7. Оформление: введение, обзор литературы, данные, методы, эксперименты, выводы.
